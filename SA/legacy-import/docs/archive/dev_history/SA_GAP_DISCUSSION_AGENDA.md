## Part 2: 關鍵決策討論

### 決策 1: 8 個 Attendance 回歸測試

**現況：**
- SA v1.9 要求 8 個回歸測試必過
- Reality: 0/8 實作
- 規格已完整定義（ATTENDANCE_REGRESSION_SPEC.md）

**討論點：**

#### Q1: 這 8 個測試是否真的是 P0？
- [ ] 是，必須立即實作（阻斷 Gate 5 完成）
- [ ] 否，可以延後（先完成其他功能）
- [ ] 部分是 P0（哪些？）

#### Q2: 測試實作的時機？
- [ ] 選項 A：立即實作（在任何新功能前）
- [ ] 選項 B：與 Auth 轉換同步進行
- [ ] 選項 C：Gate 5 最後驗收時實作

#### Q3: 如果測試失敗怎麼辦？
- [ ] 修正業務邏輯（可能需要重構）
- [ ] 調整測試規格（如果規格不合理）
- [ ] 記錄為 known issue（技術債）

**建議討論時間：** 20 分鐘

**產出：**
- [ ] 決定測試優先度
- [ ] 決定實作時機
- [ ] 定義失敗處理策略

---

### 決策 2: Auth 轉換策略

**現況：**
- JWT 基礎設施完成
- 2/7 模組已轉換（tenants, customer_service）
- 4/7 模組仍用 Header（attendance, notifications, backup, audit）

**討論點：**

#### Q1: 是否要統一為 JWT？
- [ ] 是，全部轉換為 JWT（符合 SA v1.9）
- [ ] 否，保持混合模式（Header + JWT 並存）
- [ ] 部分轉換（哪些模組優先？）

**如果選「是」：**

#### Q2: 轉換順序？
- [ ] 選項 A：一次全部轉換（Big Bang，風險高）
- [ ] 選項 B：按模組批次轉換（推薦）
  - Batch 1: attendance（核心業務）
  - Batch 2: audit（管理功能）
  - Batch 3: notifications（低風險）
  - Batch 4: backup（管理功能）
- [ ] 選項 C：按功能重要性排序（自訂）

#### Q3: 轉換期間的相容性？
- [ ] 保持 Header 作為 fallback（向後相容）
- [ ] 直接移除 Header（強制升級）
- [ ] 設定 deprecation 期限（如 2 週後移除 Header）

#### Q4: 測試更新策略？
- [ ] 同步更新測試（轉換時一起改）
- [ ] 先轉換 API，後更新測試
- [ ] 保留 Header 測試作為回歸測試

**如果選「否」（保持混合）：**

#### Q5: 如何管理兩套機制？
- [ ] 明確文件化哪些 API 用 Header，哪些用 JWT
- [ ] 設定未來轉換時間表
- [ ] 接受技術債，未來再處理

**建議討論時間：** 20 分鐘

**產出：**
- [ ] 決定是否統一為 JWT
- [ ] 定義轉換順序（如果轉換）
- [ ] 定義相容性策略
- [ ] 定義測試更新策略

---

### 決策 3: Scope 驗證與 Feature Gate

**現況：**
- Scope Checker 已實作（`scope.py`）
- Feature Service 已實作（`feature_service.py`）
- 但只有 2/7 模組使用

**討論點：**

#### Q1: Scope 驗證是否必須？
- [ ] 是，所有 API 必須驗證 Scope（符合 SA v1.9）
- [ ] 否，只有敏感 API 需要（如 entitlements）
- [ ] 部分需要（哪些？）

#### Q2: Feature Gate 是否必須？
- [ ] 是，所有 API 必須檢查 Feature Gate
- [ ] 否，只有付費功能需要
- [ ] 部分需要（哪些？）

#### Q3: 驗證順序是否必須嚴格遵守？
- [ ] 是，必須 Scope → Tenant → Feature（SA v1.9 要求）
- [ ] 否，可以彈性調整
- [ ] 只要有驗證即可，順序不重要

#### Q4: 如何套用到現有 API？
- [ ] 選項 A：與 Auth 轉換同步進行（一次改完）
- [ ] 選項 B：獨立 WP，逐個 API 加入
- [ ] 選項 C：新 API 強制，舊 API 選擇性加入

**建議討論時間：** 15 分鐘

**產出：**
- [ ] 決定 Scope 驗證範圍
- [ ] 決定 Feature Gate 範圍
- [ ] 定義套用策略
